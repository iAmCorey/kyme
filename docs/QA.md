# QA：发版前的检查

每次发版都要跑：

```bash
cargo xtask qa --release
```

全部通过才能发版；这次的报告（`target/qa/report-*.md`）随版本一起存档。平时跑 `cargo xtask qa`：它只挑和还没推送的改动有关的几项，只改了文档就什么都不跑。

## 三种跑法

| 命令 | 跑什么 | 会不会打扰你 |
|---|---|---|
| `cargo xtask qa` | 按改动挑：工作区的修改、新文件、还没推送的提交碰到了哪些文件，只跑相关的检查（对应关系在 `xtask/src/changes.rs`）。改了引擎是格式、clippy、单元测试、评测、按键场景；改了候选窗或 macOS 接入层才跑最慢的那两项 | 不会 |
| `cargo xtask qa --all` | 全部自动检查：格式、clippy、单元测试、评测、按键场景、安装包、macOS 接入层。约 1–2 分钟，改过代码后第一次会多花编译的时间 | 不会：不动输入法设置，也不占屏幕 |
| `cargo xtask qa --release` | 以上全部，再加人工检查清单和发版要求 | 人工检查要你在各个 App 里试一遍 |

改引擎时常用 `--only eval,scenarios`，两三秒跑完。检查名：`fmt` `clippy` `test` `eval` `scenarios` `bundle` `macos` `release` `manual`。

## 每项查什么

| 检查 | 内容 | 什么时候算没通过 |
|---|---|---|
| 格式 | `cargo fmt --check`，按 `rustfmt.toml` | 有文件没格式化 |
| clippy | 整个 workspace 的所有 target | 有任何警告 |
| 单元测试 | `cargo test --workspace` | 有测试失败 |
| 评测 | `eval/pinyin.tsv` 每一条的首选；打的过程中输入框显示的是打的字母；照着打的拼音不被纠错改掉（见下）；单条转换和载入词库的耗时 | 有一条不对或显示的不是打的字母、拼音被改的比例或耗时超过门槛 |
| 按键场景 | `qa/scenarios.tsv`：在模拟的输入框里按键，看最后的文字 | 有一个场景不对 |
| 安装包 | 组装 `target/app.noindex/Kyme.app`（不安装），核对 Info.plist 的必填项和版本号、控制器类名、图标、本地化字符串、词库和签名 | 有任何一项不对 |
| macOS 接入层 | 见下 | 有一个键对不上，或者耗时、内存超过门槛 |
| 发版要求 | 代码已经提交；仓库和安装包里都有 LICENSE | 没提交或者有未提交的改动、缺 LICENSE |
| 人工检查 | `qa/manual.toml` 里的 App 兼容性和观感，逐项问你 | 有一项不通过（跳过的算「要注意」） |

### 照着打的拼音不能被改

纠错只在拼不通、或者纠错的读法明显更合理时才用：打对了的拼音一个字母都不能被改掉（`naanni` 是 `na'an'ni`「那按你」，不能被读成 `nan'ni`「南宁」）。评测里有两项检查盯着这一点：

- 「本来就对」那一类的每条输入，从第一个字母打到最后一个，每一步引擎理解的拼音（`spelling`）都要和打的字母一样，也就是没被当成打错。
- 最常用的 80 个音节两两拼接（6400 个输入），同样逐个字母打，拼音被改掉的不能超过门槛（现在是 0.12%，剩下的是 `ow`→`wo`「我」这种纠错明显更合理的）。
- 带上一万个故意捣乱的本地词（词频极高）和一万个用户词（加分到顶）再跑上面两项，被改的不能变多，单条转换也不能慢过门槛。

最后一个音节还没打完时（`suho` 可能要接着打 `suhong`，也可能是「说」打反了），首选按照着打的读法，纠错的结果排在第二个候选，按 2 就能选。为什么这样设计见 [ENGINE.md](ENGINE.md)。

### macOS 接入层

用 `Kyme --qa`（自测模式）把 `qa/scenarios.tsv` 再跑一遍。自测模式里是真正的输入会话、macOS 接入代码和候选窗，只是不连系统的输入法服务，换成了一个假的输入框。每个键之后和参照会话对照：

- 这个键是输入法接住了，还是交给了 App；
- 上屏了什么；
- 输入框里正在输入的文字（marked text）；
- 正在输入时候选窗显示着，并且贴在光标那一行下方（放不下时在上方）；每个场景结束后候选窗收起来。

最后看按键处理耗时的 p95 和进程的常驻内存。自测模式用默认设置和临时的设置文件，不读你的设置，也不写日志；不挂用户词库，也就不学词；不读本地词库。

**为什么不在真的 App 里模拟打字**：试过（2026-10-27）。程序合成的字母键经系统转给输入法时，输入法收到的是控制字符，认不出是哪个字母；修饰键是好的，真实键盘也没有这个问题。各种合成方式（直接造 NSEvent、经 CGEvent、投给指定进程、投到 HID 层）结果都一样。所以系统转发按键这一段、以及各个 App 里的表现，交给人工检查清单。

### 系统的授权弹窗

macOS 启用第三方输入法时会弹窗「允许 Kyme 启用 Kyme 拼音？」，要点允许才能用。两处设计是为了少弹：

- `Kyme --install` 只启用还没启用的输入源，已经启用的不再调一遍启用接口。
- `scripts/build-app.sh` 签名时把签名要求固定成只认 bundle ID。ad-hoc 签名默认按 cdhash 认身份，每编译一次就变，系统会把每次重装都当成新的输入法。这只适合本机开发，正式发布要用 Developer ID 签名。

## 门槛

写在 `qa/gates.toml` 里：

| 门槛 | 值 | 现在（M1 Pro） |
|---|---|---|
| 单条拼音转换的最长耗时 | 5ms | 约 1.5ms |
| 词库载入 | 500ms | 约 150ms |
| 常用音节拼接时拼音被改的比例 | 0.5% | 0.12% |
| 按键处理 p95（自测模式） | 16ms | 约 4.4ms |
| 输入法常驻内存（自测模式） | 150MB | 约 120MB |

后两项是 [PLAN.md](PLAN.md) 里定的目标。耗时和机器有关，以发版用的那台机器为准。

## 加用例

**用户报的 bug，先加一条能复现的用例，再去修。**

- **评测**（引擎给出的首选）：在 `eval/pinyin.tsv` 加一行 `类别<TAB>拼音<TAB>期望的首选`，每一条都必须对。暂时做不到的放进 `eval/pending.tsv`（格式相同，用到时新建）：它只报告、不卡发版，哪条做到了会提示挪过去。
- **按键场景**（按完一串键后输入框里的文字）：在 `qa/scenarios.tsv` 加一行，写法见文件开头，期望照默认设置写。`cargo xtask qa` 会在模拟的输入框里验证它，再在 macOS 接入层逐键验证。
- **人工检查**（App 兼容性、观感）：在 `qa/manual.toml` 加一个 `[[check]]`，写清在哪个 App 里、怎么操作、期望看到什么。

## 发版流程

1. 改版本号：`Cargo.toml` 的 `workspace.package.version`，和 `crates/kyme-macos/bundle/Info.plist` 的 `CFBundleShortVersionString`（`CFBundleVersion` 加 1）。安装包检查会核对两边一致。
2. 在 `CHANGELOG.md` 里把「未发布」改成版本号和日期，然后提交。
3. 在发版用的机器上跑 `cargo xtask qa --release`，全部通过。
4. 把 `target/qa/` 下这次的报告随版本存档。
5. 打 tag、发布。签名公证和安装包到 Phase 4 再补进这个流程。
